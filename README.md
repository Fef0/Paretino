# Paretino

Paretino is an Android app for home and DIY climbing walls. Photograph your wall, let the phone find the holds, then build and log routes by tapping them.

It works offline. Hold detection runs on the phone, and your photos and routes stay on it.

## What it does

- **Masters:** a master is one physical set-up of the wall. Take a photo, mark the wall corners, then check the detected holds and fix any mistakes by hand.
- **Paths:** build routes by tapping holds on a master, with roles, colours and labels. Each path has a title, description, grade and setter.
- **Logbook:** log ascents per climber, and mark favourites and ratings.
- **Master diff:** compare two set-ups to see which holds were added, removed or changed, and which paths are affected.
- **Sharing:** export paths and back up your data.
- **LED walls (planned):** the data format and a stub for sending a path to an ESP32 over Bluetooth are in place. The link itself isn't built yet.

## Hold detection

A small YOLO segmentation model (yolo11n-seg, about 12 MB) outlines each hold rather than drawing a box around it. It runs through ONNX Runtime on tiles of the photo. The app has no OpenCV dependency; the OpenCV detector it used to have is kept only as the baseline in `ml/scripts/opencv_baseline.py`.

The model was compared with that old detector on images the test model never trained on, across 18 lighting and lens conditions such as sun stripes, low light, ultra-wide distortion and motion blur:

| Mean F1 (higher is better) | OpenCV | YOLO |
|---|---|---|
| Real gym photos (4 photos, 189 holds) | 0.31 | **0.93** |
| Simulated plywood walls (16 scenes) | 0.49 | **0.97** |

Treat these as early results. The real test set is small, no real plywood photo has been scored yet, and the test conditions resemble the training effects, so real-world robustness is probably lower. The model in the app was then fine-tuned on all the data, including the test photos, so these scores come from the evaluation version. Details and known weak spots are in [ml/README.md](ml/README.md).

## Where the training data came from

No dataset for plywood home walls exists, so the training set combines these sources:

| Source | What it gave us | How it was labelled | Licence |
|---|---|---|---|
| [Indoor Climbing Gym Hold And Route Segmentation](https://www.kaggle.com/datasets/tomasslama/indoor-climbing-gym-hold-segmentation) by Tomáš Sláma ([project](https://github.com/xiaoxiae/Indoor-Climbing-Hold-and-Route-Segmentation)) | Photos from two gyms, Boulderhaus Heidelberg and Smíchoff | By hand on a subset, automatically on the rest | CC BY-SA 4.0 |
| [Wikimedia Commons](https://commons.wikimedia.org/) | 279 free-licence photos of climbing walls | Automatically | Per file, see [ml/DATA_CREDITS.md](ml/DATA_CREDITS.md) |
| Generated by this project | Simulated plywood walls, made by pasting real hold cut-outs from the gym photos onto generated plywood | From the known cut-out outlines | Same as the source photos |

Automatic labels came from an existing hold detector ([jwlarocque/yolov8n-freeclimbs-detect-2](https://huggingface.co/jwlarocque/yolov8n-freeclimbs-detect-2), AGPL-3.0) for boxes and [SAM](https://huggingface.co/facebook/sam-vit-base) (Apache-2.0) for outlines. Labels that fell on people were removed.

Every training image was then altered with simulated phone effects: exposure, colour casts, shadows, noise, lens distortion, blur and compression.

The photos are not stored in this repository. The scripts that download and build the dataset are in [ml/scripts](ml/scripts).

## Try it

Download the APK from [Releases](https://github.com/Fef0/Paretino/releases). It needs Android 8.0 or newer on a 64-bit ARM phone. Early builds are pre-releases.

## Build

You need Android Studio with its bundled JDK. The app runs on Android 8.0 (API 26) or newer.

```sh
./gradlew assembleDebug
./gradlew testDebugUnitTest
```

The model is already included at `app/src/main/assets/models/holds.onnx`, so you only need the Python pipeline to retrain it. See [ml/README.md](ml/README.md).

## Status

This is an early personal project. Speed hasn't been measured on a real phone yet, and the interface is due for a redesign. Planned work is in [TODO.md](TODO.md).
